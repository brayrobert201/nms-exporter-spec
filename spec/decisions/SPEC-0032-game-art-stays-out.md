# SPEC-0032: Game art stays out

## Context

Several features want things that are Hello Games' property: HUD icons for hotspots and markers,
the 16 portal glyphs, part sizes derived from scene files, a modified entity file for the Harvest
All mod, and item names and mission titles from the language tables. Committing them is
convenient — a fresh checkout would just work — but redistributes the game's assets, and a public
repository makes that redistribution to anyone.

## Decision

- **Art is never committed.** Icons and glyphs are extracted by `nms-icons` / `nms-glyphs`
  (SPEC-0023) into `data/icons/` and `data/glyphs/`, both gitignored, and served from there.
  The same applies to any texture, model, font or sound.
- **Modified game files are never committed or shipped.** The Harvest All mod is rebuilt from the
  user's own packed file on install (SPEC-0025); the repository contains the recipe (which file,
  which field, which value), not the MBIN.
- **Derived numbers are the boundary.** `data/part_footprints.json` holds only six numbers per
  object id and a provenance string — no geometry, no names, no art. It is regenerated by
  `nms-footprints` (SPEC-0024). The original keeps it gitignored and regenerates; a public rebuild
  may choose to do the same, which is the conservative reading.
- **Game text is regenerated, not shipped, in a public rebuild.** `nms_tables.json` contains item
  names, recipe names and mission titles from the language files. It is gitignored and
  generated from the installed game (SPEC-0021); the loader's error names the script that builds
  it. Keep only a small hand-written fixture of made-up ids for tests if needed.
- **Cited excerpts are short and purposeful.** Compendium sources from `nms-pak cite`
  (SPEC-0026) are line ranges of converted data tables, chosen to support a specific claim, with
  provenance. A public rebuild should keep its cited excerpts outside the public repository, or
  replace them with the field name, value and location, which this spec repository does.
- **Pages work without any of it.** Every consumer falls back: shapes instead of icons, hex
  digits with glyph names instead of glyph images, points instead of footprints, an explanatory
  message instead of a planner.

## Alternatives considered

- **Commit the PNGs and JSON** — easiest for users; redistributes art and text.
- **Draw our own icons and glyphs** — legal and portable, but the point of the glyphs is to match
  the portal the player is looking at; hand-drawn approximations invite misdialling.
- **Download from a community mirror at runtime** — the same redistribution, done by someone else,
  plus a network dependency and no build key.

## Consequences

- A fresh install needs one extra step: run the extraction scripts after installing the pak tools.
  The README of a rebuild lists them in order: tables, icons, glyphs, footprints.
- After every game update the user re-runs them; the scripts are idempotent. Footprints is the
  slowest, since it unpacks and converts about 1,000 placement scenes plus their references.
- Revisit if Hello Games publishes terms that explicitly allow redistribution of UI assets for
  fan tools.
